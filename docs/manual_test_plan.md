# План ручного тестирования

Приоритетный чек-лист составлен по требованиям [README](../README.md). Выполняйте проверки на тестируемой странице; для каждой фиксируйте статус, фактический результат и ссылку на дефект при наличии. `P0` — критичный сценарий, `P1` — важная проверка, `P2` — дополнительная проверка. Прочерк означает, что проверка ещё не выполнена.

Во всех сценариях, кроме проверяемого условия, используйте корректные данные: будущую дату, время 10:00–11:00, комнату «Малая», 2 участника, имя и корректную почту. Для проверки сегодняшнего времени учитывайте локальное время системы и выбирайте интервал, допустимый по остальным правилам.

Зафиксируйте браузер, ОС, дату проверки, вопросы и допущения, проверенные области, риски и ограничения. Если проверку выполнить не удалось, укажите причину вместо результата.

## Условия и ограничения проверки

Проверено 23 ноября 2026 года на опубликованной странице `https://rcsi-science.github.io/demo-roomly/` с помощью Playwright и Chromium 156.0.8078.4 в Docker (Linux/WSL2, часовой пояс браузера UTC). Пользователь также прошёл пункты TC-01–TC-13 вручную; TC-14 добавлен позже и проверен автотестом. Приведённые результаты были зафиксированы при автоматизированной проверке через интерфейс браузера. Проверен один браузер и один размер окна. Для TC-13 наблюдались запросы при отправке и в течение 500 мс после неё; более поздняя отправка не проверялась.
